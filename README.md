# WireDeck

**Self-hosted панель управления VPN на AmneziaWG и WireGuard.** Один контейнер,
один процесс — поднимает туннель, раздаёт конфиги клиентам и показывает живую
статистику трафика в тёмной, аккуратной веб-морде на русском языке. По умолчанию
поднимается на [AmneziaWG](#обход-блокировок-amneziawg) — тот же WireGuard, но
с обфускацией, которую не ловит сигнатурный DPI.

- **Пользователи в пару кликов** — имя ввёл, конфиг получил. Ключи, IP-адреса и
  preshared-ключи генерируются автоматически.
- **QR-код для мобильных** — навёл камеру в приложении, подключился. Плюс
  кнопки «Скачать .conf» и «Скопировать». Для приложения **AmneziaVPN** панель
  отдаёт ссылку `vpn://…`: переслал в мессенджер — подключение добавилось в одно
  нажатие, вообще без камеры.
- **Обход блокировок из коробки** — новые установки поднимаются на
  [AmneziaWG](#обход-блокировок-amneziawg): тот же WireGuard, но с обфускацией,
  которую не ловит сигнатурный DPI.
- **Вкл/выкл одним тумблером** — отключённый пользователь мгновенно теряет
  доступ, остальные даже не замечают (применяется через `wg syncconf`, без
  разрыва соединений).
- **Живая аналитика трафика** — кто онлайн, кто сколько скачал и выгрузил:
  графики за 24 часа / 7 дней / 30 дней, топ пользователей, история по часам
  в SQLite.
- **Тёмная веб-панель** — React + Tailwind, без внешних CDN и телеметрии.
- **Один контейнер** — Node-процесс и WireGuard живут вместе, данные — в одном
  volume. Никаких сайдкаров и брокеров.

## Быстрый старт

Понадобится сервер с root-доступом и открытыми портами `51820/udp` и
`8080/tcp`. Рекомендуем **Debian 13** — на нём WireDeck тестируется;
Debian 12 и Ubuntu 22.04+ тоже подойдут.

Всё одной командой:

```bash
curl -fsSL https://raw.githubusercontent.com/romashuhov/vpn/main/deploy/install.sh | sudo bash
```

Скрипт всё сделает сам, без вопросов: склонирует репозиторий в `/opt/wiredeck`,
поставит Docker, определит публичный IP, запишет `deploy/.env`, соберёт и
запустит контейнер, а в конце выведет адрес панели — `http://<ваш-IP>:8080`.
Свой адрес вместо автоопределённого: `WG_HOST=vpn.example.com ./start.sh`.

**Сразу откройте панель** — первый вход попросит придумать пароль
администратора. Не откладывайте: пока пароль не задан, задать его может любой,
кто дотянется до порта.

То же самое через git (каталог — любой на ваш вкус):

```bash
git clone https://github.com/romashuhov/vpn /opt/wiredeck && cd /opt/wiredeck && ./start.sh
```

Публичный адрес можно задать заранее: `WG_HOST=vpn.example.com ./start.sh`.

### Управление

| Скрипт | Что делает |
|---|---|
| `./start.sh` | первичная настройка и запуск (повторный запуск безвреден) |
| `./logs.sh` | логи контейнера, `Ctrl+C` — выйти |
| `./restart.sh` | перезапуск; применяет изменения `deploy/.env` |
| `./update.sh` | `git pull` + пересборка, только если есть новые коммиты |
| `./stop.sh` | остановка; данные остаются в volume `wiredeck_data` |
| `./uninstall.sh` | удалить контейнер и образ; данные сохраняются (снести и их — `--purge`) |
| `./check-ip.sh <IP>` | проверить, доступен ли адрес сервера **из России** (см. ниже) |

База, ключи и статистика живут в volume `wiredeck_data` и переживают
пересоздание/пересборку контейнера.

### Проверка доступности адреса

Если у пользователей из России не открывается панель или не работает VPN,
первым делом стоит понять, не заблокирован ли сам IP-адрес сервера:

```bash
./check-ip.sh 203.0.113.10
```

Скрипт подключается к вашему адресу с узлов check-host.net по всему миру и
отдельно показывает российские. Если мир подключается, а Россия — нет, адрес
заблокирован и нужен другой (желательно из другой подсети и у другого хостера).
Узлы сервиса стоят в дата-центрах, поэтому «зелёный» результат не гарантирует
работу у домашних и мобильных операторов — там фильтрация строже.

## Обход блокировок: AmneziaWG

Ванильный WireGuard легко детектится: у его рукопожатия фиксированная сигнатура,
и системы DPI (в России — ТСПУ) режут такой трафик, даже не зная, что внутри.

**AmneziaWG** — форк WireGuard, который эту сигнатуру ломает: перед рукопожатием
отправляются мусорные пакеты, к пакетам рукопожатия добавляются случайные
префиксы, а magic-заголовки типов пакетов заменяются на произвольные числа.
Криптография и производительность — те же, меняется только то, как трафик
выглядит снаружи.

**Новые установки WireDeck сразу идут на AmneziaWG** — `start.sh` при первичной
настройке дописывает в `deploy/.env` строку `WG_ENGINE=awg`. Уже развёрнутые
установки после `./update.sh` остаются на обычном WireGuard: смена движка
обязывает перевыдать конфиги всем клиентам, и делать это молча нельзя.

### Что нужно клиентам

Подойдёт любое из двух приложений Amnezia — панель отдаёт конфиг в обоих
форматах, переключатель **AmneziaWG / AmneziaVPN** висит прямо над QR-кодом:

- **AmneziaWG** — форк официального клиента WireGuard. Вкладка «AmneziaWG»:
  текстовый `.conf`, QR-код с ним, кнопки «Скачать .conf» и «Скопировать».
- **AmneziaVPN** — основное приложение Amnezia. Оно ждёт собственный упакованный
  формат, поэтому вкладка «AmneziaVPN» отдаёт **ссылку `vpn://…`** и отдельный
  QR под неё. Ссылку достаточно переслать человеку в мессенджер: на телефоне она
  открывает приложение и добавляет подключение в одно нажатие, без камеры.

Официальный клиент WireGuard в режиме AmneziaWG не подойдёт — он не понимает
параметры обфускации.

| Платформа | Где взять AmneziaWG |
|---|---|
| Android | Google Play — «AmneziaWG», либо APK: [amneziawg-android/releases](https://github.com/amnezia-vpn/amneziawg-android/releases) |
| iOS | App Store — [AmneziaWG](https://apps.apple.com/app/id6478942365) |
| Windows | [amneziawg-windows-client/releases](https://github.com/amnezia-vpn/amneziawg-windows-client/releases) |
| Android (альтернатива) | [WG Tunnel](https://wgtunnel.com/) — открытый клиент, использует движок AmneziaWG |
| Роутеры | Keenetic (KeeneticOS 4.2+), GL.iNet (4.9+), OpenWrt (пакеты `awg-openwrt`) — импорт файлом `.conf` |

AmneziaVPN есть в Google Play, App Store и на [amnezia.org](https://amnezia.org)
(Windows, macOS, Linux).

В приложении: **`+` → Scan QR code** (навести на код в панели) либо **импорт
файла** `.conf`. Если QR не сканируется — скачайте `.conf` кнопкой в панели,
перешлите файл и откройте его в приложении: этот способ работает всегда. Для
AmneziaVPN самый простой путь вообще без QR — переслать ссылку `vpn://…`.
Панель сама показывает эту подсказку рядом с QR-кодом.

### Переключить существующую установку

```bash
echo 'WG_ENGINE=awg' >> deploy/.env   # или WG_ENGINE=wg — вернуться обратно
./restart.sh
```

Если строка `WG_ENGINE=` в `deploy/.env` уже есть — отредактируйте её, а не
дублируйте. Что движок действительно сменился, видно на дашборде: в карточке
«Сервер» появляется бейдж **AmneziaWG**.

После рестарта **обязательно перевыдайте конфиги всем клиентам**: откройте
каждого пользователя в панели и отдайте ему новый QR/`.conf`. Старые конфиги
работать перестанут — клиент и сервер должны использовать одинаковые параметры
обфускации. Пользователей, ключи и статистику это не затрагивает: пересоздавать
никого не нужно.

Параметры обфускации (`Jc/Jmin/Jmax`, `S1/S2`, `H1…H4`) генерируются один раз,
сохраняются в базе и больше не меняются — иначе после каждого рестарта у всех
клиентов отваливалась бы связь. Руками их трогать не нужно; при необходимости
любой параметр переопределяется переменной окружения (см. таблицу ниже).

### Честно о пределах

Обфускация — не серебряная пуля. Сигнатуры AmneziaWG цензорам тоже известны, и
при достаточно упорной блокировке помогает уже не протокол, а смена IP-адреса
или хостера: если заблокирован сам адрес сервера, никакая маскировка внутри
туннеля этого не исправит. AmneziaWG заметно поднимает шансы, но гарантий не
даёт.

## Переменные окружения

Все переменные опциональны, кроме `WG_HOST` (в проде).

При запуске в Docker через `deploy/.env` прокидываются `WG_*`, `AWG_*`,
`COOKIE_SECURE` и `POLL_INTERVAL_MS` (см. `environment` в `docker-compose.yml`); остальные
(`PORT`, `HOST`, `DATA_DIR`, `WEB_DIST`, `WG_MOCK*`) фиксированы образом и
нужны для разработки или bare-metal-запуска без Docker.

| Переменная | Дефолт | Смысл |
|---|---|---|
| `WG_HOST` | — | Публичный IP или домен сервера; попадает в `Endpoint` клиентских конфигов. **Обязательна в проде** |
| `WG_PORT` | `51820`* | UDP-порт WireGuard; маппинг портов в compose подхватывает его автоматически |
| `PANEL_PORT` | `8080`* | Порт веб-панели на хосте (внутри контейнера всегда 8080) |
| `WG_INTERFACE` | `wg0` | Имя WireGuard-интерфейса |
| `WG_SUBNET` | `10.8.0.0/24` | Подсеть VPN; сервер занимает первый хост (`.1`) |
| `WG_DNS` | `1.1.1.1` | DNS, который получают клиенты |
| `WG_ALLOWED_IPS` | `0.0.0.0/0, ::/0` | `AllowedIPs` в клиентском конфиге (весь трафик через VPN) |
| `WG_PERSISTENT_KEEPALIVE` | `25` | Keepalive клиента, секунды |
| `WG_MTU` | `1280` | MTU туннеля (сервер и клиентские конфиги). Дефолт консервативный — работает в мобильных сетях и за кривыми путями; `off` — не указывать (дефолт WireGuard 1420, чуть быстрее, но может ловить PMTU-blackhole) |
| `WG_ENGINE` | `wg` | Движок туннеля: `wg` — обычный WireGuard, `awg` — [AmneziaWG](#обход-блокировок-amneziawg) с обфускацией против DPI. Новым установкам `start.sh` сам прописывает `awg`; смена значения требует перевыдачи всех клиентских конфигов |
| `AWG_JC` / `AWG_JMIN` / `AWG_JMAX` | генерируются | Мусорные пакеты перед рукопожатием: количество (1–128) и размеры в байтах (`0 ≤ Jmin < Jmax < 1280`). **Менять не нужно** — генерируются автоматически при первом запуске и хранятся в базе |
| `AWG_S1` / `AWG_S2` | генерируются | Размеры случайных префиксов к пакетам Init/Response (`S1` ≤ 1132, `S2` ≤ 1188). **Менять не нужно.** Должны совпадать у сервера и клиента |
| `AWG_H1` … `AWG_H4` | генерируются | Magic-заголовки четырёх типов пакетов (5 … 2147483647, все четыре разные). **Менять не нужно.** Должны совпадать у сервера и клиента |
| `WG_MOCK` | авто | `1`/`true` — мок-режим без реального WireGuard; по умолчанию мок везде, кроме Linux |
| `WG_MOCK_SEED` | `1` в мок-режиме | Засеять демо-пользователей и историю трафика |
| `PORT` / `HOST` | `8080` / `0.0.0.0` | HTTP-порт и адрес веб-панели |
| `COOKIE_SECURE` | `0` | `1` — флаг `Secure` на сессионную cookie. Включайте **только когда панель уже за TLS**: по голому `http://IP:8080` браузер отбросит такую cookie и войти будет невозможно |
| `DATA_DIR` | `./data` (в Docker — `/data`) | Каталог с SQLite-базой и конфигом интерфейса |
| `POLL_INTERVAL_MS` | `15000` | Период опроса статистики WireGuard |
| `WEB_DIST` | `../../web/dist` от `server/dist` | Путь к собранной SPA |

\* Если дефолтный порт на сервере уже занят (свой WireGuard, что-то на 8080),
`start.sh` при первой установке сам подберёт ближайший свободный (+1) и
зафиксирует его в `deploy/.env` — дальше порт не меняется, ведь он зашит в
выданные клиентские конфиги.

## Разработка

Нужен Node.js 22+. Docker и Linux не нужны:

```bash
npm install
npm run dev
```

На Windows и macOS автоматически включается **мок-режим**: вместо реального
WireGuard работает симулятор с пятью демо-пользователями и правдоподобной
историей трафика за 30 дней — панель сразу «живая», трафик движется. Панель
разработки: **http://localhost:5173** (Vite проксирует `/api` на сервер,
который слушает :8080).

Сборка прода: `npm run build`, запуск: `npm start`.

## Архитектура

Коротко (подробный контракт — в [ARCHITECTURE.md](ARCHITECTURE.md)):

- **Сервер** — Node.js + Fastify + better-sqlite3. Один процесс: REST API,
  раздача SPA, управление WireGuard и сбор статистики. Ключи X25519 генерируются
  через `node:crypto`, бинарник `wg` для этого не нужен.
- **WireGuard** — интерфейс поднимается через `wg-quick`, изменения пиров
  применяются через `wg syncconf` — существующие туннели не рвутся. Статистика —
  `wg show dump` каждые 15 секунд, дельты складываются в почасовую таблицу SQLite.
  При `WG_ENGINE=awg` то же самое делают `awg-quick` / `awg` из
  amneziawg-tools — CLI и формат вывода у форка идентичны, в контейнере
  используется userspace-реализация `amneziawg-go`.
- **Веб** — React 19 + Vite + Tailwind CSS 4, графики recharts, QR — `qrcode`.
  Всё статикой отдаёт тот же сервер, внешних запросов нет.
- Интерфейс WireGuard переживает рестарт панели: при остановке процесса туннель
  не опускается, при старте — конфигурация идемпотентно синхронизируется.

## Безопасность

- **Спрячьте панель за reverse proxy с TLS.** Панель слушает голый HTTP, наружу
  порт 8080 лучше не светить. Пример с [Caddy](https://caddyserver.com)
  (TLS-сертификат получится автоматически):

  ```
  vpn.example.com {
      reverse_proxy 127.0.0.1:8080
  }
  ```

  После этого уберите проброс `8080:8080` из compose наружу (или закройте порт
  firewall-ом), добавьте `COOKIE_SECURE=1` в `deploy/.env` (cookie сессии
  перестанет уходить по случайному http-запросу) и заходите только через
  `https://vpn.example.com`.
- **Сильный пароль администратора.** Панель управляет доступом ко всему VPN;
  пароль хранится как scrypt-хэш, но перебор простого пароля никто не отменял.
  Минимум 8 символов — это минимум, а не рекомендация.
- **Приватные ключи клиентов хранятся в базе сервера.** Это осознанный
  трейдофф: только так панель может в любой момент показать QR-код и заново
  отдать/пересобрать конфиг клиента. Практический вывод: файл базы
  (`/data/wiredeck.db`) и её бэкапы — такой же секрет, как ключи сервера;
  доступ к серверу равен доступу ко всем туннелям.
- Порты наружу нужны только два: `51820/udp` (WireGuard) и `443/tcp` (панель
  за reverse proxy). Всё остальное можно закрыть.
